Архитектура проекта: статический лэндинг на Vercel

Главная идея

Весь сайт — это обычные файлы: один HTML, один CSS, несколько JS. Никакого сервера, который всегда работает и стоит
денег. Хостинг берёт на себя Vercel — он сам раздаёт файлы пользователям из CDN (сеть серверов по всему миру, файлы
кэшируются близко к пользователю).

Пользователь
    │
    ▼
Vercel CDN
├── index.html        ← вся страница
├── css/landing.css   ← стили
├── js/i18n.js        ← переключение языка
├── js/landing.js     ← форма, модалка, меню
└── assets/           ← картинки, логотипы

---
Как работает форма (самое важное)

Когда пользователь нажимает "Отправить" — страница не перезагружается. JS делает запрос к /api/submit и ждёт ответа:

Браузер
│  fetch POST /api/submit  { name, email, phone }
▼
api/submit.py   ← это и есть "serverless function"
│                 (Python-файл, который Vercel запускает
│                  только когда приходит запрос)
├──► Supabase (PostgreSQL) — сохраняет заявку
└──► Telegram Bot API     — отправляет уведомление

Serverless function (функция без постоянного сервера) — это когда у тебя нет сервера, который работает 24/7. Вместо
этого есть файл с кодом, и платформа (Vercel) запускает его только тогда, когда приходит HTTP-запрос. Запрос пришёл →
функция запустилась → ответила → выключилась. Это бесплатно на небольших объёмах.

---
Как устроен каждый слой

1. index.html — страница

Обычный HTML. Переводы встроены через атрибут data-i18n прямо в теги:
<h1 data-i18n="hero_title">...</h1>
<button data-i18n="form_send">...</button>
JS потом ищет все такие элементы и подставляет текст на нужном языке.

2. js/i18n-data.js + js/i18n.js — мультиязычность

i18n-data.js — просто объект со словарями:
window.__LOCALES__ = {
ru: { hero_title: "Заголовок", form_send: "Отправить" },
en: { hero_title: "Title",     form_send: "Send" },
kk: { ... }
}

i18n.js определяет язык (из localStorage или браузера), находит все [data-i18n] элементы и меняет текст. Без
перезагрузки страницы, без запросов к серверу.

3. js/landing.js — форма

Перехватывает submit формы, делает fetch POST /api/submit с JSON, показывает "Отправлено" или ошибку. Тоже без
перезагрузки страницы.

4. api/submit.py — серверная логика

Один Python-файл, класс handler. Vercel смотрит: папка api/ → файл submit.py → маршрут /api/submit. Делает три вещи:
- Валидирует данные (имя обязательно, нужен email или телефон)
- Сохраняет в Supabase через HTTP-запрос к их REST API
- Отправляет уведомление в Telegram

5. vercel.json — конфигурация

{
"crons": [{ "path": "/api/ping", "schedule": "0 9 * * *" }],
"headers": [
    { "source": "/assets/(.*)",
    "headers": [{ "key": "Cache-Control", "value": "max-age=31536000" }] }
]
}

- crons — расписание: каждый день в 9:00 Vercel сам вызывает /api/ping. Это нужно потому что Supabase на бесплатном
тарифе "засыпает" после нескольких дней без активности — пинг не даёт ему уснуть.
- Cache-Control: max-age=31536000 — браузер кэширует картинки и CSS на год. Пользователь скачивает их один раз.

6. Supabase — база данных

Supabase — это PostgreSQL (обычная реляционная БД) с REST API поверх неё. Вместо того чтобы поднимать свой
PostgreSQL-сервер, используешь их сервис. Есть бесплатный тариф. Запрос к базе — обычный HTTP POST с JSON.

Переменные окружения (секреты, которые не коммитятся в git) задаются в панели Vercel:
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_SERVICE_KEY=eyJ...
TELEGRAM_BOT_TOKEN=123:ABC...
TELEGRAM_CHAT_ID=-100...
CRON_SECRET=случайная_строка

Главное отличие от Django-версии

Django-версия — полноценный сервер: Django + Gunicorn + Nginx + Docker + SQLite. Он постоянно работает и требует VPS
(платный сервер). Эта версия — только файлы + две маленькие функции, всё остальное делают сторонние сервисы. Для
лэндинга с формой этого более чем достаточно.
